# MinerU-試用報告.md

## 1. 執行摘要 (Executive Summary)

- **一句話總結**：MinerU 是一款功能強大的開源 PDF 解析工具，具備卓越的複雜文檔處理能力（公式、表格），但其 AGPL-3.0 授權對閉源商業產品整合構成重大合規風險，較適合內部研發、數據清洗或作為獨立服務部署。
- **關鍵發現**：
    1. **解析精度高**：針對學術論文、教科書等複雜版面（多欄、公式、表格）有極佳的還原度，優於傳統 OCR 工具。
    2. **多模態支援**：原生支援將 PDF 轉換為 Markdown 與 JSON，並能自動提取圖片、表格與公式（LaTeX），對 LLM 訓練數據準備非常友善。
    3. **部署彈性**：提供 Command Line、Python API 及 Docker 部署方式，且支援 CPU/GPU/MPS 多種硬體加速。
    4. **最大潛在風險**：**授權傳染性 (AGPL-3.0)**。核心代碼與部分模型（YOLO）採用 AGPL 協議，若將其整合至 SaaS 服務或分發軟體，可能強制要求開源整個專案代碼。

## 2. 產品規格與授權分析 (Licensing & Versions)

| 比較項目 | 開源版 (Open Source) | 線上服務/API (MinerU.net) |
| :--- | :--- | :--- |
| **取得方式** | GitHub / PyPI / Docker | Web 介面 / HTTP API |
| **授權模式** | **AGPL-3.0** (具傳染性) | 依服務條款 (通常為訂閱或按量付費) |
| **商用可行性** | **受限**。需開源修改後的代碼（包含網路服務端）。 | **高**。透過 API 呼叫，通常不涉及代碼傳染，但需確認數據隱私條款。 |
| **部署成本** | 高。建議使用 GPU (16GB+ VRAM 推薦) 以獲得合理速度。 | 低。無需維護硬體，按使用量付費。 |
| **企業功能** | 無內建 SSO、Audit Log。需自行實作或透過外層封裝。 | 完整帳戶管理與 API 金鑰機制。 |

> [!WARNING]
> **授權警示**：專案明確指出目前依賴的 YOLO 模型遵循 AGPL 協議。雖然官方計畫未來替換為更寬鬆授權的模型，但在現階段（v2.5.4），若企業計畫將其整合至閉源商業產品中，必須諮詢法務部門。

## 3. 重點面向評估 (Key Evaluation)

### 功能完整性 (Completeness)
針對「智能 PDF 解析」核心需求，MinerU 覆蓋率極高：
- **文檔結構還原**：能精準識別標題、段落、清單，並按人類閱讀順序重組。
- **特殊元素處理**：
  - **公式**：自動轉換為 LaTeX 格式，準確率高。
  - **表格**：支援複雜表格結構識別，並轉換為 HTML/Markdown 格式。
  - **圖片**：自動提取並保留上下文引用關係。
- **多語言支援**：支援 84 種語言的 OCR 識別，包含繁體中文。

### 系統整合性 (Integration)
- **介接難易度**：**中等**。
  - **優點**：提供標準 Python SDK 與 CLI 工具，且輸出格式為通用的 Markdown/JSON，極易於被下游應用（如 RAG 系統、搜尋引擎）索引與處理。官方提供 Docker Image，大幅降低環境配置難度。
  - **挑戰**：硬體資源需求較高。若要達到即時處理（Real-time）效能，必須配置高階 GPU（如 NVIDIA 4090 或伺服器級顯卡）。若僅用 CPU，處理速度可能無法滿足高併發場景。
- **生態系支援**：支援主流格式，且與 LLM 生態系（如 LlamaIndex, LangChain）整合潛力大（數據前處理）。

## 5. 評估結論 (Conclusion & Recommendation)

### 綜合評分：A-
*(扣分項主要來自於 AGPL 授權限制與較高的硬體門檻)*

### 對管理層的具體建議
1. **場景區隔策略**：
    - **推薦採用**：內部知識庫建置、RAG 系統數據清洗、學術研究輔助。這些場景通常不涉及對外分發軟體，AGPL 風險可控。
    - **謹慎評估**：直接嵌入至對外銷售的套裝軟體 (On-premise Software) 或作為核心 SaaS 功能模組。若必須使用，建議採用「服務隔離」架構（將 MinerU 封裝為獨立服務，透過 API 溝通），或直接採購其商業 API 服務以規避授權風險。
2. **資源投入**：
    - 若決定自建，需編列 GPU 伺服器預算。
    - 建議優先使用 Docker 部署以減少環境相依性問題。
3. **持續關注**：
    - 追蹤官方未來是否如承諾替換掉 AGPL 授權的模型模組，屆時可重新評估商業整合的可行性。
